# RoboCasa365 输入一致性与实际训练覆盖诊断

记录时间：2026-09-27T07:37:04.938594+00:00。本轮没有新训练更新或策略试验；当前云端仍在完成 50k Atomic18 最终评估。

## 训练与评估的观测路径

Atomic18 与 Composite16 共 34 任务，各按固定随机种子抽取一条训练和一条验证演示，取首帧、中间帧、末帧，共 68 条演示、204 个窗口。使用真实训练 adapter，另外将相同记录的 RGB、原始 parquet state 和指令经过正式 observation_arrays、NPZ 序列化，再执行从冻结 evaluate_policy.py 提取的实际输入构造表达式，最后调用正式 Cosmos 输入构造函数。

全部窗口的 state、相机拼图和 Cosmos 视频输入逐项相同、最大误差 0；语言字符串相同。state 为原始 16D 补零到 64D，两边均没有额外 state 归一化。Cosmos 输入为 [1,1,3,128,384]；当前 action-only 训练和推理均没有 GT future 视频输入。交换相机和倒置 state 的反例均被检出。

此项两条路径使用同一批录制 RGB，没有重新渲染环境、加载模型权重或执行神经网络预测。因此不能据此排除所有新场景视觉分布差异、相机标定问题或学习不足。证据：`runs/robocasa365_input_equivalence_20260927/audit/report.json`。

## 关键松手阶段与后续训练判断

复核此前已有的 Cabinet 松手窗口预测：训练和验证各仅 4 条演示、每条 2 次噪声。50k 在实际执行的前 8 步内，训练窗口 open 命令召回为 24/32（75%），验证为 11/32（34.38%）；这些是相关命令位置，不是 32 条独立演示或策略试验。25k 对应为 4/32 与 8/32。小样本显示训练拟合改善明显、验证改善较弱，尚不能把全部失败归为唯一根因。

50k 验证窗口未执行的后 8 步 open 召回为 36/64（56.25%）；8 个相关预测 chunk 中 2 个在前 8 步没有任何 open、后 8 步有 open。这提示可以在开发场景检查动作执行时域，但不能直接据此改最终评估 H8，或声称 H16 会提高成功率。证据：`diagnosis_20260927/release_head_tail_review.json`；本项复用已有 CPU 预测，没有新增预测或 rollout。

Composite16 的训练帧数为 5,403,990。若仍采用均匀选任务、再均匀选帧，50k×global64 的方案预计覆盖约 43.19% 的不同观测起点；该值是解析期望，不是已执行的 Composite 训练结果，也不是成功率。

当前判断：已有证据不支持将低成功率简单归为 12D 动作映射或这次检查覆盖的输入构造错误，也不能只凭步数认为已充分学习。完成当前 1,800 次闭环评估，保留已验收的 Composite 首轮方案；使用开发评估和关键阶段的训练/验证差距决定是否延长训练、调整采样或开展 Video DiT 对照，不单凭覆盖率加步数。当前冻结快照和 50k 调度没有修改，不能把未来调整写成已执行。
