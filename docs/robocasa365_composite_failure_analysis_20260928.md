**Composite 早期失败分析：必要的前期操作尚未完成**

诊断核验截至 2026-09-28 02:19 UTC。这里的 2k、10k 均指从 Atomic18 50k 动作分支初始化后，新增的 Composite 训练步数。

目前能确定的直接原因是：这些案例中，策略没有完成启动设备、打开抽屉或抓取食材等必要的前期操作。重放准确复现了这些失败，支持对失败阶段的解释；为何模型生成了这些无效动作，仍需区分关键动作学习不足、场景感知与泛化、闭环误差累积等原因。

**取烤面包的同场景对照已经完成。** 两个权重使用相同初始 XML 和完整物理状态，均执行 3,000 个控制步。每条轨迹的 375 次保存查询状态，以及重放的初始、最终完整物理状态，与各自原评估的误差全部为 0。

| 检查项 | Composite 2k | Composite 10k |
| --- | ---: | ---: |
| 两根吐司机拨杆的全程读数 | 均为 0 | 均为 0 |
| 启动带面包的吐司机 | 未发生 | 未发生 |
| 抓到面包／放入盘子 | 均未发生 | 均未发生 |
| 末端相对初始位置的最大偏移 | 0.781 m | 0.915 m |
| 初始末端到面包中心距离 | 0.380 m | 0.380 m |
| 最终末端到面包中心距离 | 1.123 m | 0.875 m |
| 发出夹爪关闭命令的控制步比例 | 3.2% | 0% |

官方拨杆启动阈值为 0.9。任务要求先压下拨杆启动吐司机，再取面包放入盘子；成功判定必须满足“曾在面包在槽内时启动吐司机”、面包入盘、夹爪远离面包。因此没有启动吐司机已经足以导致失败。末端移动距离不代表有效进展，末端到面包中心的距离也不能代替末端到拨杆的距离；这里判定未启动依据的是实际拨杆状态。夹爪关闭命令比例不等于抓取率，也不是按下拨杆的充分条件。

两个其他任务提供了补充证据：

| StirVegetables，同 seed100，12 与 2k | 两种蔬菜、锅铲的抓取步数均为 0；两种蔬菜入锅步数均为 0；官方搅拌成功累计时间为 0。失败发生在食材入锅之前。没有完成本任务的 10k 阶段诊断。 |

加上此前 12 步的取面包和取吸管案例，累计诊断 8 条不同的已保存策略轨迹，共 21,450 个控制步、2,682 次保存查询。它们的初态、终态和保存查询状态都与各自原评估一致。全部采用 seed100，只覆盖 3 种任务；不能外推为所有 Composite 失败的共同根因，也不增加策略评估的样本数。

**训练确实在更新，但平均 loss 的改善还没有转化为这两个案例的关键步骤突破。**

当前使用 7,271 条训练演示、806 条验证演示，约 540 万训练帧。四卡、global batch 64；State Encoder、Action Encoder/Decoder 和 Action DiT 均训练，Video DiT、VAE、Qwen 冻结。GetToastedBread 本身有 455 条训练演示、51 条验证演示、588,266 个训练帧。

训练日志记录的验证 flow matching loss：2k 为 0.070952，10k 为 0.065189，下降约 8.1%。训练 loss 的连续 100 步均值从 1901–2000 步的 0.07863 降到 9901–10000 步的 0.06765。它们都是动作预测目标的平均指标，不能证明拨杆操作、抓取或闭环恢复已学会。当前采样为先均匀选任务、再均匀选训练帧；关键接触和阶段切换是否得到足够有效监督，尚未做阶段覆盖审计。

初始化的 Atomic18 50k 总成功率为 279/1,800（15.5%）；其中从吐司机取物为 8/100、开抽屉为 10/100。它提供了已学习的动作分支，但这些相关基础技能本身仍弱，不能把 Atomic50k 当作已具备可靠操作能力的起点。这是支持优先检查基础动作学习的背景证据，不是这次失败的因果证明。

**已核验范围及未解决的问题。**

- 已完成的保存动作审计覆盖预测、反归一化、截断、官方二值阈值、12D 重排和仿真实收动作；当前检查没有发现顺序或尺度错误，控制器合同为 base 坐标系的 delta 控制。
- 此次精确重放支持“失败来自原评估中实际执行的动作”的判断。它不重新运行模型，不验证原评估相机图像与训练数据的像素、标定或分布完全一致。
- 已有 204 个录制窗口的训练／评估输入构造一致性检查覆盖同一批录制 RGB，不能替代新场景的视觉检查。
- 取烤面包的评估指令与数据集的自然语言任务说明相同；本次额外抽查的 3 条 parquet 演示使用该自然语言说明的 task_index。此项不是全数据语言审计。
- 原专家 demo 的接触漂移仍是单独未解决的问题。这次重放的是模型自己的动作，不能据此宣称专家 demo replay 已修复。

**后续处理顺序。** 已批准的四卡训练与 10k／25k／50k 评估流程继续，权重独立备份保持运行。本报告不修改正在运行的训练快照。

1. 完成 10k 的 320 次开发评估，并保留逐任务结果；同时使用启动设备、开抽屉、抓取等阶段指标检查进展。
2. 针对上述失败，比较训练演示与独立验证演示中的接近、接触、夹爪切换窗口。训练窗口也预测差时，优先检查关键阶段监督、采样和动作分支拟合；训练窗口好而验证／新场景差时，优先检查感知和泛化。这些阶段预测比较尚未执行。
3. 若录制窗口预测正确但闭环仍持续偏离，再用相同开发场景检查初始相机输入和动作执行长度。保持当前正式评估协议，单列诊断对照。
4. 仅在证据支持视觉适配不足后，设计同起点、同数据、同场景的 Video DiT 部分解冻对照。目前没有证据保证多训或解冻一定有效。
