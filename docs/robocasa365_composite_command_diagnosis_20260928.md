**下一步训练建议与已启动的命令预测对照**

当前建议：继续已批准的 Composite 50k 主线和权重备份，先用训练／验证对照决定优先修正的环节。现有失败阶段证据不足以保证增加步数或解冻 Video DiT 有效。

已固定选择 GetToastedBread、DeliverStraw、StirVegetables，每任务 20 条训练演示和 20 条验证演示，共 120 条不同演示。选择种子为 2809；两个划分完全遵循当前训练 manifest，没有重新划分。

每条演示取首帧，以及首次连续四帧张开命令转为连续四帧关闭命令前四帧的窗口，共 240 个窗口。它是夹爪命令切换标签，不是物理接触、抓取或吐司机拨杆标签。选择不依赖模型预测，没有因为缺失切换而替换演示；本次所选 120 条演示都存在该切换。

实际数据预检和独立复核已完成：逐条对照原始 parquet 的 state、未来 action、语言和 mask；保存的三相机拼图为 [1,3,128,384]。训练、验证各 20 条／任务，240 个窗口全部通过。尚未完成模型预测结果的独立核验，不能把输入验收当作模型拟合结论。

CPU 进程已启动，使用当前云训练的 149 文件冻结源码副本，加一份独立诊断入口。它比较 Composite 新增 2k、10k 两份动作权重，共享冻结 Cosmos 特征，使用配对噪声 123、124 和四次积分。完整预测保留 16 步，主要统计实际执行的前 8 步。计划保存 960 个 action chunk；噪声重复和同演示多个窗口不是新的独立演示，也不是策略评估次数。图像、状态、目标、特征和预测会保存，以便复算及后续检查点复用。

已经发现一个会影响诊断解释的因素：专家的起步命令不总是机械臂动作。

| 任务 | 抽样训练起始前 8 步的底盘模式命令占比 | 抽样验证起始前 8 步的底盘模式命令占比 |
| --- | ---: | ---: |
| GetToastedBread | 0% | 0% |
| DeliverStraw | 80% | 97.5% |
| StirVegetables | 48.125% | 20% |

每格来自 20 条演示、160 个相关控制时刻。原始 mode 和 gripper 标签均为 -1、+1。取吸管验证演示中，17/20 条在前 8 步的手臂平移命令全为零，20/20 条包含非零底盘运动命令。因此不能把该组较低的手臂 MAE 直接解释为泛化更好；需要检查 control mode 的正负类召回、底盘动作、实际手臂模式下的动作误差，以及同一组目标上的零动作基线。当前接口保留并训练完整的 base/mode 维度，此发现不等于发现接口删维错误，也不证明取面包失败由底盘模式导致。

后续独立汇总必须核对两个预测 NPZ 的观察编号、配对噪声、原始 target/mask、checkpoint 身份，并独立复算反归一化、前 8 步指标和逐演示指标；对比基线及有效控制模式，避免只用平均 loss 或重复命令数量下结论。

| 对照中观察到的现象 | 优先处理方向 |
| --- | --- |
| 训练演示的关键命令也预测较差 | 查阶段采样、mode／夹爪稀有切换和动作分支拟合；必要时做单任务拟合诊断。 |
| 训练演示较好，独立验证／新场景较差 | 检查场景分布与视觉输入，再决定是否做同起点的 Video DiT 部分解冻对照。 |

这些是诊断优先级，不能仅凭一个指标唯一确定根因。CPU 精度和随机抽样与 CUDA 评估并非逐值相同；本次没有 optimizer 更新、没有额外 GPU 申请、没有新增成功率试验，也没有改动运行中的训练或仿真源码。
