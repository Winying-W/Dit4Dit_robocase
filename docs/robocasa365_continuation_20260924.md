## 自动复核与实际诊断的边界

新增 `review_evaluation.py` 从保存的真实结果重新核对分母、分子、任务、seed、权重身份、归一化和完整 horizon，并逐条独立重建预测到 simulator 实收 action 的转换。它输出逐任务成功率、Wilson 区间、裁剪/夹爪/底盘行为指标，每任务按固定 seed 顺序选择最多 3 条失败和 1 条成功轨迹供检查。缺试验时不输出完整总体成功率，接口短测和 demo 初始化不得进入正式结果。

`watch_evaluation_reviews.py` 仅用 CPU 观察当前目录，在开发/最终报告发生变化后自动生成独立复核文件，并保存心跳。它不新建、停止或重启 GPU 作业。进程和真实运行证据位于 `runs/robocasa365_continuation_20260924/`；需检查心跳新鲜度，不能把一次启动当作永久存活保证。

该自动复核不会仅凭零成功率或 loss 指认根因。完整失败诊断仍包含视频检查、观测对齐、必要的保存动作重放和受控实验。失败轨迹的 replay 不算新增策略试验；初始 scene/state 不一致时不能用重放里的物理事件解释原始轨迹。原 GT episode0/3 的接触漂移仍未完全解决。

## 评估后的决策顺序

| 证据 | 下一步 |
| --- | --- |
| 动作顺序、反归一化、delta/absolute、base 参考系、控制缩放、binary threshold 或实际 simulator 命令不一致 | 先修对应接口并重做真实短验收；保留异常结果，不据此判断训练好坏。新评估记录修复版本。 |
| 动作链通过，但部分任务弱 | 检查这些任务的失败阶段、数据覆盖、三相机顺序/时间/预处理、state 顺序和范围、任务文本、action chunk 时间对齐与 padding；与成功任务比较。 |
| 全部或多数 Atomic 在 10k 为零/极低成功 | 优先检查跨训练/推理的观测一致性，选择开发失败轨迹定位第一处偏离，再用少量明确标记的训练场景过拟合诊断可学性。小诊断不替代大数据训练及独立评估。 |
| 接口通过，10k→25k 同协议开发成功率提升 | 支持续训到已声明的 50k；同时看逐任务是否退化。只有初始 XML/完整物理状态相符的场景可作严格配对比较。 |
| 训练拟合好、独立开发场景弱 | 优先检查场景泛化、任务平衡与数据覆盖；增加有效数据或调整采样，不仅延长步数。重新划分/归一化时记录新的实验身份。 |
| 动作分支续训收益停滞，且接口/观测检查通过 | 从同一可访问 checkpoint 开新对照：动作分支继续训练 vs 动作分支加部分 Video DiT 解冻，数据、归一化、随机种子、更新预算和开发场景保持可比。先短验收，再延长。 |
| 原生 GR1 复现实验也异常 | 优先修模型加载、推理或环境版本；原生 GR1 与 PandaOmron 的数据和 controller 各用原生接口，结果分开报告。 |

候选部分解冻从 Video DiT blocks16/17 的小范围开始；当前实现保留官方 stop-gradient，action loss 不回传视频，视频更新依赖独立 video flow-matching loss。此前仅有 CPU 梯度路由证据，不能宣称该解冻方案已训练成功。Qwen 文本编码器和 VAE 保持冻结。论文 DiT4DiT 的联合训练章节支持同时适配两个 DiT 并冻结文本/VAE，但具体解冻层数和学习率必须由本项目的受控对照确定，不能把 OpenVLA 的微调结论直接当作 DiT4DiT 的最优配置。

参考：`docs/research/dit4dit_2603.10448.txt` 中 Joint Training of Video and Action；`docs/research/vla_finetuning_2502.19645.txt` 仅作为其他 VLA 的微调设计参考。
