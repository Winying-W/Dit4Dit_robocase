# 开发 checkpoint 的场景配对检查

新增 `scripts/robocasa365/compare_development_checkpoints.py`，用于比较 Composite 第 12 步启动基线、10k 和 25k 开发评估。该 CPU 工具先重新审计两边的全部已保存动作，再核对任务、种子、归一化、基座、执行时域和场景协议，最后逐条比较初始 MJCF 与保存的 MuJoCo 物理状态。

必须覆盖清单声明的全部任务和全部开发种子。只要有一对场景不一致，就不输出整套评估的配对提升、胜负计数或区间；不会静默删除不一致的样本。最终评估不能输入这个训练决策工具。两份评估各自的完整成功率仍保留在独立审计结果中。

全部场景一致时，报告新增成功、丢失成功、成功率差和探索性 95% 区间。区间按种子块重采样：同一种子下所有任务一起采样，以保留共用场景种子带来的任务间相关性。这里的推断限于固定任务和这组开发场景，20 个种子块的区间较粗；退化区间不能证明模型等效，也不是未见任务泛化结论。

21 项相关测试通过。真实重新审计了 Atomic10k 与 Atomic25k 的完整 360 对开发记录：332 对一致、28 对不一致，工具正确返回 `scene_mismatch` 并抑制整套配对提升。原有单独成功率 11/360 和 25/360 没有被改写。这次检查没有新增策略试验、训练更新或成功率样本。

检查对象是保存的 MJCF 和 flattened state，并不比较每帧渲染像素或全部隐藏求解器/控制器缓存，不能作为 GT demo replay 漂移已修复的证明，也不能替代冻结/部分解冻 Video DiT 的受控实验。

独立快照与真实检查结果保存在 `runs/robocasa365_development_comparison_20260927/`。`composite_plan.json` 已列出三组后续比较及命令；只有双方完整开发评估都完成时才执行。目前 Composite 对比数量仍为 0，主训练与 Atomic 最终评估继续运行。
